## 1. 场上这两个

Kaggle 规则：一天 5 次提交，**只有最新的 2 个是活跃的**，失活是**按提交时间**，
不是按分数。所以「场上」永远是最后提交的两个。

| 提交号 | 名字 | 天梯分 | 局数 | 状态 |
|---|---|---:|---:|---|
| `55489160` | `kawashigi-k06` | **2612.3** | 94（74–20） | 活跃 · **挑战者，仍在爬** |
| `55484175` | `topline` | **2391.6** | 59（46–13） | 活跃 · **对照组，已收敛** |

这两个是**一次对照实验**，不是两次独立尝试。它们的**源队伍、市场层、打包方式
完全相同，只有「录自哪一局」不同**。设计目的是检验我们的本地指标（面板胜率）
能不能预测天梯分。

**结果：能。** k06 面板 98.5% → 天梯 2612.3；k01 面板 92.4% → 天梯 2391.6，
差 220.7 分，方向与面板一致。完整记录见 `docs/RUNS.md` 的
《The prospective test of the panel, resolved》。

| `55489160` | `agents/champ/k06.py` | カワシギ · episode **92135733** · seed 458483945 · 2026-08-11 | `86a7a74cd349` |


## 3. 从零重建（不需要我机器上的 data/）

```bash
git clone https://github.com/jwj1342/Kaggriculture.git
cd Kaggriculture
bash tools/bootstrap.sh          # 只在 venv/ 不存在时
source setup_env.sh              # 在集群和个人电脑上都能跑

# 1) 把 3.2 MB 的剧本库快照装回本地索引（371 条线）
python tools/tracelib.py import dist/tracelib.json.xz

# 2) 生成カワシギ的全部 17 条线，k01 / k06 在里面
python tools/wrap.py --team "カワシギ" --top 40 --min-score 0 \
    --out agents/champ --prefix k
```

`dist/tracelib.json.xz` 是 tracked 的，里面有全部 371 条线的完整 720 回合动作日志，
外加每条线的**真实天梯战绩**（`wins` / `plays`）。**这是唯一必需的数据文件。**

`agents/` 下面的东西全部是 git-ignored 的生成物，永远不要手改，改了下次重新生成就没了。

## 4. 验证你重建的和榜上的是同一个

不要靠肉眼。这个环境里**非法动作是静默无操作** —— 错了不报错、不扣分，
看起来和「策略不好」一模一样。所以要让文件自己回答一个已知问题：

```bash
python - <<'PY'
import json, base64, zlib
from kaggle_environments.agent import get_last_callable
for sub, local in (("2026-08-13-topline", "agents/champ/k01.py"),
                   ("2026-08-13-kawashigi-k06", "agents/champ/k06.py")):
    ns = {}
    exec(compile(open(f"submissions/{sub}/plan.py").read(), "plan", "exec"), ns)
    submitted = json.loads(zlib.decompress(base64.b85decode(ns["BLOB"])).decode())
    fn = get_last_callable(open(local).read(), path=local)
    assert fn.__name__ == "agent", f"{local}: 框架会加载 {fn.__name__}，不是 agent"
    ok = all(fn({"step": s}).get("farmer") == submitted[s].get("farmer")
             for s in range(0, len(submitted), 37))
    print(f"{sub:<32}{local:<24}{'一致 ✓' if ok else '不一致 ✗'}")
PY
```

**为什么必须检查 `fn.__name__`**：比赛框架用 `get_last_callable` 加载 `main.py`，
它返回**模块里最后一个被绑定的可调用对象**。在 `agent` 之后再绑定任何函数
（包括 `_INNER = agent` 这种），加载到的就是错的那个，而且**不报错**，
每个变体都会跑出一模一样的分数。详见 `CLAUDE.md` 的 Agent contract。

## 5. 这两个能有多强，别抱错期待

```
カワシギ（录音出处，天梯第 1）        3235.7
我们的复制品                          2604.9
────────────────────────────────────────────
开环重放税                            630.8 分，保留 80.5%
```

**一段录音不等于录它的那个 agent。** 对手是自适应的，会读棋盘、会响应价格；
录音只是把某一局的动作原样重放，换个棋盘就有一部分动作变成无效。这 630 分就是
这件事的代价。

换一句话说：**这条路线的上限已经量出来了。** 完美复制天梯第 1 是 3235.7，
前 10 名门槛是 3061.4 —— 天花板本身在奖金区内，但需要 **94.6% 的保留率**，
我们做到 80.5%。剩下的差距不在包装层里（见下），只能靠**自己写会读棋盘的 agent**。

### 顺带：包装层已经被完整定价了

2026-08-13 跑了五波受控实验共 312,000 局，把市场层每个组件逐个关掉重测：

| 组件 | 实场价值 |
|---|---|
| 卖单排序 `_SORT_KEY='impact'` | **+4.1 点**（唯一有效的） |
| 终局读棋盘控制器 | **$4** on $83,465 |
| 终局清仓 / race 权重 / 促销策略 | **0** |
| `_RESERVE` / `_RAMP_*` / `_SHED_PRESSURE` | 死代码，且 `_RESERVE` 是坏的 |

**总共 4 个点，而且已经在最优设置上。** 不要再去调这些参数了，已经调到底了。
完整分析和方法见 **`docs/ANALYSIS.md`**（11 节，中文，从「怎么做干净的实验」讲起）。

## 6. 为什么现在不要提交

三条，任意一条都足够：

1. **会挤掉对照组。** 失活按提交时间。现在提交，`55484175`（已收敛的对照组）
   立刻失活，正在进行的比较就断了。
2. **k06 还没收敛。** 它现在 94 局、滑动 30 局败率 26.7%，还在四局赢三局的爬升期。
   **一个提交在输掉大约三分之一的对局之前，它的分数只是个还在动的地板**，
   不能拿来比较、不能写进结论。规则见 `docs/SUBMISSION_POLICY.md` 第 7 条。
3. **提交频率会毁掉可读性。** 天梯每小时只打约 10 局。一天连提五次，
   每个 agent 只能分到 4–12 局 —— 既排不出名次，也诊断不了任何东西。
   **半天最多一次。**

想提交新东西，先在 `docs/RUNS.md` 里写清楚**是什么本地结果支持它**，
以及**你打算用什么判据判断它成功还是失败**（在结果出来之前写）。
