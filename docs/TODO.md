## ○ 给本地场地建一个能预测天梯的评分（最高优先级）

**现状**：`docs/ROADMAP.md` §10.5 —— 本地胜率与源队伍天梯分的相关性是
`pearson -0.038 / spearman -0.054`（n=100）。**当前没有任何本地指标能预测天梯强度。**
在修好之前，本地跑出来的每一个名次都只能说明「这段录音换棋盘还能不能用」。

**为什么值得做**：这是所有其它工作的前置条件。路线 C 要搜剧本，搜索需要一个目标函数；
现在这个目标函数被证明与要优化的东西无关。继续往下做就是在优化噪声。

**已经有的材料**：`agents/wrapped/` 的 100 条线各自带着源队伍的真实天梯分，
这是一份 **100 行的标注数据**。可以拿它筛：什么样的本地测法能和这一列对上。
先试的两个方向 ——

1. **同队多局取聚合**：一支队伍的多条线取中位数而不是单条，看队级聚合是否相关。
   THUNDER THUNDER 有 16 条、HealthStone 14 条、Seb 11 条，够做。
2. **换被测量**：胜率之外，试终局金额、对固定基线的分差、跨种子方差。

**做完怎么算数**：某个本地统计量对源队伍天梯分的 spearman 稳定超过 0.4（n≥60，
且在留出的队伍上复现）。达不到就如实记下「找不到」，那本身也是结论。

### ◐ 第一个干净的检验：把源队伍固定在 #1（作业 479962）

§10.5 测出零相关，最大的混淆项是「不同队伍」—— 一条线的天梯锚点是**队伍的自适应
agent**，而我们手上是**一局录音**，这个错配跨队伍时最严重。**固定队伍就能消掉它。**

`カワシギ`（#1 @ 3,236.5）在库里有 **17 条线**，此前只建了 5 条（`w57` / `w76` /
`w98` / `d08` / `d25`），而这 5 条在同一面板上是 **26.3% – 92.4%**。

```bash
python tools/wrap.py --team "カワシギ" --top 40 --min-score 0 \
    --out agents/champ --prefix k          # 17 条全建
```

**17 条已建、已测**（对 top10 面板 96 种子双向，每条 1,920 局）：

```

k01 92.4% <- 就是已提交的 topline      k13 92.4%   k12 90.9%   k05 89.5%   k02 87.9%
k11 44.9%   k03 32.8%   k07 32.1%   k04 30.9%   k09 30.1%   k08 22.7%
```

**同一支队伍、同一周的 17 局录音，面板胜率 22.7% – 98.5%** —— 跨度比整个 100 方
场地还大。§10.5 在同队条件下不但成立，而且更强。

**剩下的一步：提交 `k06`。** 它比已提交的 `k01` 高 6.1 个百分点（各 1,920 局，
区间不重叠），而 `k01` 已有天梯锚点 **2,359.5**。这是这个仓库第一次能对本地度量做
**前瞻性**验证，而不是事后找相关：

* 天梯跟着涨 → 面板胜率在**同队条件下**有预测力，本地评分问题解决一半。
* 天梯不动或下降 → 连这个条件下都没有，这条待办要换方向。

**做完怎么算数**：`k06` 的天梯分收敛后（按规则 7，滑动窗口败率 ≈1/2）写进 `RUNS.md`，
与 `k01` 的 2,359.5 并列，无论哪个方向都记。

**注意**：源队伍的天梯分评的是他们**当前的自适应 agent**，而我们手上是**一局录音**。
这个错配会压低任何相关性的上限，不能全部归给测法。这一条要写进结果里。
