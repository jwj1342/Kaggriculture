```bash
python tools/tracelib.py pull \
    --dates 2026-08-07,2026-08-08,2026-08-09,2026-08-10,2026-08-11 \
    --per-date 700 -j 8
```

## ○ 给本地场地建一个能预测天梯的评分（最高优先级）

**现状**：`docs/ROADMAP.md` §10.5 —— 本地胜率与源队伍天梯分的相关性是
`pearson -0.038 / spearman -0.054`（n=100）。**当前没有任何本地指标能预测天梯强度。**
在修好之前，本地跑出来的每一个名次都只能说明「这段录音换棋盘还能不能用」。

**为什么值得做**：这是所有其它工作的前置条件。路线 C 要搜剧本，搜索需要一个目标函数；
现在这个目标函数被证明与要优化的东西无关。继续往下做就是在优化噪声。

**已经有的材料**：`agents/wrapped/` 的 100 条线各自带着源队伍的真实天梯分，
这是一份 **100 行的标注数据**。可以拿它筛：什么样的本地测法能和这一列对上。
先试的两个方向 ——

1. **同队多局取聚合**：一支队伍的多条线取中位数而不是单条，看队级聚合是否相关。
   THUNDER THUNDER 有 16 条、HealthStone 14 条、Seb 11 条，够做。
2. **换被测量**：胜率之外，试终局金额、对固定基线的分差、跨种子方差。

**做完怎么算数**：某个本地统计量对源队伍天梯分的 spearman 稳定超过 0.4（n≥60，
且在留出的队伍上复现）。达不到就如实记下「找不到」，那本身也是结论。

### ✓ 第一个干净的检验：把源队伍固定在 #1 —— 已完成，通过

`k06`（面板 98.5%）对 `k01`（面板 92.4%），同队伍、同市场层、同打包方式，
只换录自哪一局。**结果：2612.3 对 2391.6，高 220.7 分，方向与面板一致。**

`k01` 已收敛（滑动 30 局败率 40.0%，分数已回落）；`k06` 局数是它的 1.6 倍
且仍在爬。三种事前判据里命中「明显高于」。

**面板胜率在源队伍固定的条件下能预测天梯。** 这是这个仓库第一个与真实强度有
验证关系的本地指标，而且是**事前**预测不是事后相关。

**但这是 n=2。** 一次比较，不足以支持跨队排名，也不足以直接拿它当搜索目标 ——
要拿它做几千轮搜索之前，需要第二次确认。细节见 `RUNS.md`
「The prospective test of the panel, resolved」。

## ○ 路线 C：搜一条自己的剧本

**现状**：一步都没开始。`agents/wrapped/` 里 100 条全是别人的剧本，
`benchmarks/strongest.py` 也是。

**为什么值得做**：`docs/ROADMAP.md` §7 里唯一还有前 10 天花板的路线，而且现在这个
天花板是量出来的：**照抄录音最多到 2,359.5，第 10 名要 3,089.0**（`RUNS.md`

而前 10 名门槛 3,061.4 —— 完美复制榜首是 3,235.7，天花板在奖金区内，卡住的是保留率。

**做之前先想清楚**：交付物是**剧本 + 市场包装**两样，不是只有剧本 —— §4 测过，裸录音
对每一个带包装的 agent 都是 0%。

**现在被上面那条挡住了。** 搜索需要一个目标函数，而目前唯一可用的是**面板胜率**
（定义见 `VALIDATING.md` 开头），它本身还没被证明能预测天梯。拿一把没校准的尺子
去做几千轮搜索，只会精确地优化到错误的地方。**先关掉上面那条。**

**成本**：约一周，可能失败。算力不是瓶颈（1,536 核约每小时 200 万局），
瓶颈是跨种子跨对手的评估设计。
