## 1. 分布式收集 + 中心学习器（已同意试）

现状：单节点 32 核 ≈ 800–1,300 步/秒。目标 ~4 倍。

- 形态：N 个收集作业（各自 VecEnv + 当前权重快照）写轨迹 shard 到
  `$SCRATCH`；一个学习器进程消费 shard、更新权重、发布新快照。
- 难点：PPO 是 on-policy。收集器权重滞后 → 要么高频同步快照（简单，先试
  这个：每 1–2 个 iteration 一次），要么上 IMPALA/V-trace 重要性校正。
- 沿用仓库惯例：shard 是 JSONL/NPZ 追加写，绝不碰共享数据库；学习器单点写。
- 显式否决项：单节点 64 核方案（2026-08-15 用户否决，排队代价不值）。

## 2. 张量化引擎（新引擎，绝不动旧的）

棋盘 = (C, 10, 10) 张量，规则 = 张量变换（与图像管线同构），PyTorch 实现,
CUDA 上批量并行几千个环境——价值不在单局加速，在**批量**。

- 落点：新目录（如 `rl/tensor_env/`），参考实现是
  `reference/engine/kaggriculture.py`，**逐条规则移植**。
- 验证门槛（硬性）：与 kaggle 引擎在相同 (seed, 双方动作序列) 下逐步比对
  状态 digest，**逐字节一致**才可用于训练。仓库 §11 的教训：引擎理解错
  一点点，训出来的就是错误世界的最优解。
- 分阶段：(a) numpy 单环境正确性版 + digest 比对挂具；(b) torch 批量版；
  (c) CUDA 版。每阶段都先过验证门槛再进下一阶。
- GPU 申请注意：集群规则"永不申请 GPU"针对的是 deepcopy 密集的单线程

- 风险登记：市场逐单位 lockstep 结算、原子 PLANT 校验、每日 RNG
  （seed×1e6+3 ^ day）这三处最容易移植错。
